## Фаза 1 — Каркас (недели 1–3)

## Фаза 2 — Ядро MVP (недели 4–8)

- [ ] Запись поимки: форма (справочник видов, вес/длина, снасть, приманка), GPS-точка
- [ ] Фото к записи: камера/галерея, клиентское сжатие, превью, загрузка в Storage
- [ ] Оффлайн-запись + sync engine (досылка очереди)
- [ ] Список поимок: лента с фильтрами (вид, место, период)
- [ ] Места: сохранение точки с карты/из поимки, список мест
- [ ] Карта (Яндекс): точки поимок, сохранённые места, погода в точке
- [ ] Статистика v1: по видам, местам, периодам, снастям; трофеи

## Фаза 3 — Доводка до «сезона» (недели 9–12)

- [ ] Корзина (мягкое удаление), редактирование записей
- [ ] Статистика «погода vs клёв»: улью по давлению/ветру/времени суток

- [ ] Тестирование на реальных выездах, правки UX по итогам

- [ ] Дистрибуция друзьям: облачный проект Supabase ([ADR-0011](adr/0011-dev-environment.md)), staging, инвайты вручную

## Фаза 4 — Публичный этап (после MVP)

- [ ] OAuth (Google, VK/Яндекс), восстановление пароля
- [ ] Открытая регистрация + лимиты/тарифы хранения фото
- [ ] Дневник выездов (UI поверх готовой таблицы `fishing_trips`)
- [ ] Push-уведомления PWA о благоприятном прогнозе
- [ ] Прогноз клёва (ML/эвристики на накопленной статистике)
- [ ] i18n (архитектура уже i18n-ready)
- [ ] Монетизация (требует отдельного ADR)

## Правила приоритизации

1. Оффлайн-надёжность важнее фич: лучше меньше экранов, но ноль потерянных записей.
2. Всё, что не отвечает на вопрос «где/когда/на что клевало», — в конец очереди.
3. Каждое новое интеграционное решение (провайдер, сервис) — сначала черновик ADR.
