# ADR-0007: Фото — облако + thumbnails, сжатие на клиенте

- **Статус:** Принято
- **Дата:** 2025-09-22

## Контекст

Фото улова — ядро UX («улика трофея»), но делается на смартфоне: исходники камеры 3–8 МБ, сеть на водоёме слабая. Нужны: надёжное хранение вне устройства, быстрый показ лент, оффлайн-создание записей с фото, контролируемые затраты на трафик и storage.

## Решение

1. **Оригинал + превью.** Клиент перед загрузкой генерирует превью (WebP, ≤ 480px, canvas) и сжимает оригинал (JPEG, ≤ 2048px, ~85% качества) — за счёт этого трафик падает в ~10 раз.
2. **Хранение — Supabase Storage**, bucket `catch-photos`, приватный; доступ по **signed URL** с TTL. Путь: `{user_id}/{catch_id}/{uuid}.jpg` + `thumb_{uuid}.webp`.
3. **Метаданные в Postgres** (`catch_photos`): размеры, пути, связь с поимкой.
4. **Оффлайн:** blob лежит в IndexedDB-очереди (ADR-0004) до подтверждения сервера; локально UI показывает локальный blob, после sync — превью по signed URL.
5. **Лимит на пользователя:** 2 ГБ на этапе 1 (проверка на Edge Function/триггере), превышение — мягкое предупреждение. Публичный этап пересматривает лимиты и тарифы отдельным ADR.
6. Удаление фото — вместе с мягким удалением поимки (файлы чистим джобом при финальном удалении из корзины).

## Альтернативы

- **Только локально (IndexedDB)** — нет затрат на хостинг, но iOS evictable storage может молча вычистить фото; потеря трофеев недопустима.
- **Гибрид «локально всегда, облако по флагу»** — двойная логика показа и двойные состояния; усложнение без ясной ценности на этапе 1.
- **Uploadify/сторонний image-CDN (Cloudinary)** — Processing из коробки, но лишняя зависимость и оплата; клиентского сжатия достаточно.

## Последствия

### Позитивные
- Трафик и storage под контролем даже в слабой сети; лента быстро рендерится по превью.
- Приватный bucket + signed URL — фото не утекают по ссылкам.
- Клиентское сжатие не требует серверных воркеров.

### Негативные / риски
- Качество зависит от браузерного canvas — приемлемо для соцсетевого формата, оригиналы при желании сохраняются на телефон пользователем (исходный файл не трогаем — камера оставляет его в галерее).
- 2 ГБ/юзер требует мониторинга; на 100 друзей это ≤ 200 ГБ — в рамках планов Supabase.

### Нейтральные
- EXIF: гео из EXIF сознательно не доверяем — координаты берём из GPS API устройства в момент записи.
