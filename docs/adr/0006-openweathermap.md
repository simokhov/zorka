# ADR-0006: OpenWeatherMap как погодный провайдер

- **Статус:** Принято
- **Дата:** 2025-09-22

## Контекст

Погоде отведена двойная роль: (1) автоматическое обогащение поимки снимком погоды в момент ловли — навсегда хранится с записью; (2) текущая погода и прогноз для мест ловли. Нужны: текущая погода, прогноз 5 дней, API-ключ не в клиенте, свободный лимит достаточный для этапа 1. Аудитория — РФ/СНГ; морская рыбалка в скоупе, но не критична на MVP.

## Решение

**OpenWeatherMap (OWM)** — endpoint'ы Current Weather + 5-day Forecast. Доступ только через Edge Function Supabase `get-weather` с серверным кэшем в `weather_cache` (TTL: current 30 мин, forecast 3 ч, координаты округляются до 0.02°). Клиент никогда не вызывает OWM напрямую.

Клиентский код работает с интерфейсом `WeatherProvider` (`getCurrent`, `getForecast`); OWM — первая реализация.

## Альтернативы

- **Stormglass** — специализирован для моря (волны, приливы), но: меньше кэшируемых «сухопутных» данных, дороже, ключ тоже требовал бы прокси. Отложен до этапа морских фич.
- **Яндекс.Погода API** — хорошо для РФ, но заметно дороже и с меньшим free tier.
- **Open-Meteo** — бесплатный без ключа; рассматривался, но OWM выбран как более предсказуемый по лимитам/стабильности и с большим комьюнити; Open-Meteo — первый кандидат на замену в `WeatherProvider`, если OWM перестанет устраивать.

## Последствия

### Позитивные
- 1000 бесплатных вызовов/день + наш кэш → с запасом на этап 1–2.
- Единый формат снимка погоды, который денормализованно хранится в `catches.weather` — статистика не зависит от жизни провайдера.

### Негативные / риски
- Модель качества прогноза OWM в глубинке средняя — для «погода в момент поимки» (main use case) не критично, т.к. это фактически измерение, а не прогноз.
- Погода в оффлайн-поимке прикладывается при первом успешном sync (дозапрос по координатам и времени): допускаем, что это ретроспективные данные (архив OWM) или ближайший доступный снимок — фиксируем стратегию дозаполнения в реализации.
- Превышение лимитов → 401/429: Graceful degradation (поля погоды остаются пустыми, запись сохраняется; UI не блокируется).

### Нейтральные
- Хранение снимка погоды как jsonb, а не FK на кэш — осознанная денормализация.
