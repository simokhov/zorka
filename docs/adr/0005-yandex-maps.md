# ADR-0005: Яндекс.Карты

- **Статус:** Принято
- **Дата:** 2025-09-22

## Контекст

Нужны: интерактивная карта точек поимок и сохранённых мест, геокодинг названий, работа в России и СНГ (основная аудитория). OpenStreetMap-базы (Leaflet/MapLibre) требуют отдельной заботы о тайлах, рендеринге и качестве покрытия местности; Google Maps — платный и юридически неудобен в РФ.

## Решение

Используем **Яндекс.Карты JS API** как картографический движок. При этом весь код работы с картой изолирован в модуле `map-provider` (интерфейс: `renderMap`, `addMarker`, `geocode`, `reverseGeocode`), UI не знает о Яндекс API. Ключ ограничиваем HTTP-реферером в Кабинете разработчика Яндекса.

## Альтернативы

- **Leaflet/MapLibre + OSM-тайлы** — бесплатно и без ключей, но: сами подбираем тайл-провайдера, качество и скорость тайлов в регионах ловли нестабильны, геокодинг подключать отдельно (Nominatim с лимитами).
- **2GIS** — хорош для городов, слаб для водоёмов и сельской местности.
- **Google Maps** — цена и недоступность биллинга в РФ.

## Последствия

### Позитивные
- Отличное покрытие РФ/СНГ, включая берега и сельскую местность; встроенный геокодинг; знакомый UX для аудитории.

### Негативные / риски
- **Платные лимиты загрузок** (бесплатная квота ограничена). Смягчение: ленивая инициализация карты (карта не грузится на экранах, где не нужна), режим «список без карты», кэш тайлов браузером, мониторинг квоты.
- Ключ в клиенте (неизбежно для JS API) — ограничение по домену + рефереру, не абсолютная защита, но принято индустрией.
- SDK — самый тяжёлый сторонник в бандле: грузим динамически, только на map-экранах.

### Нейтральные
- Изоляция `map-provider` оставляет путь на MapLibre, если квоты/условия Яндекса станут проблемой (в роадмапе фазы 4).
