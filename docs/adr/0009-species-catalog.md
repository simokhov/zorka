# ADR-0009: Встроенный справочник видов рыбы

- **Статус:** Принято
- **Дата:** 2025-09-22

## Контекст

Поимке нужен вид рыбы — главный аналитический ключ (статистика по видам, трофеи). Варианты: свободный ввод с автокомплитом (загрязняет статистику опечатками и «судак/Судак/судачок»), внешний таксономический API (лишняя зависимость), кастомные виды у пользователя (усложнение модели).

## Решение

**Встроенный справочник** `species` — таблица, наполняемая миграцией-сидом (виды средней полосы РФ, ~60 на MVP: имя RU + латинское + семейство + флаг хищника + иконка). Пользователь только выбирает (поиск по имени, RU-раскладка). Пополнение справочника — только через миграции, по запросам пользователей.

Роадмап-расширение (не MVP): поле «свой вид» — создаётся по заявке пользователя, но это отдельное решение, текущая схема не мешает (в `catches.species_id` добавится логика fallback).

## Альтернативы

- **Свободный ввод + автокомплит по фактам** — максимум гибкости, но статистика по видам разваливается на десятки дублей; чистка потом — дороже, чем справочник сейчас.
- **Справочник + кастомные виды сразу** — покрывает гибриды/экзотику, но усложняет RLS и UI выбора на этапе, когда неизвестен реальный спрос.
- **Внешний таксономический API (FishBase)** — огромное покрытие, но: неполные русские имена, зависимость и латенси для оффлайн-выбора. Оффлайн требовал бы локальной копии — тогда уж собственный сид.

## Последствия

### Позитивные
- Чистая статистика по видам с первого дня; оффлайн-поиск работает из локального кэша (таблица маленькая).
- Идентификаторы стабильны для будущей аналитики «клёв vs погода».
- Иконки/эмодзи видов централизованы — консистентный UI.

### Негативные / риски
- Пользователь не найдёт редкий/гибридный вид — на MVP принимаем (друзья ловят известные виды); заявки на пополнение — быстрый процесс через миграцию.
- Поддержка справочника — наша ответственность; обновления едут с релизами.

### Нейтральные
- Таблица глобальная, RLS — только `select`; пополнение — привилегия миграций.
