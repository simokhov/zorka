# ADR-0001: PWA как форма приложения

- **Статус:** Принято
- **Дата:** 2025-09-22

## Контекст

Приложение «Зорька» — мобильное, для использования на водоёмах. Нужны установка на домашний экран, работа без сети и минимум затрат на дистрибуцию. Пользователи — автор и друзья (этап 1), позже публичная аудитория. Нативные приложения требуют сторов, подписей разработчика и двух платформ; адаптивный сайт не даёт установки и оффлайна.

## Решение

Делаем **Progressive Web App**: mobile-first веб-приложение с manifest, service worker, иконкой на домашнем экране. Никаких нативных обёрток на этапе MVP.

## Альтернативы

- **Адаптивный сайт** — быстрее MVP, но не решает оффлайн и установку, ключевые ценности продукта.
- **Нативные приложения (Swift/Kotlin)** — лучший доступ к камере/GPS, но двойная разработка и сторы на этапе «я и друзья».
- **React Native / Capacitor-обёртка** — полезно для push и сторов позже; Capacitor можно добавить поверх того же кода в фазе 4 без переписывания.

## Последствия

### Позитивные
- Одна кодовая база, мгновенный деплой, без сторов и ревью.
- Service worker даёт оффлайн-кэш ассетов (фундамент ADR-0004).
- Установка «на экран» на iOS и Android.

### Негативные / риски
- **Push-уведомления на iOS** требуют iOS 16.4+ и установки на домашний экран — откладываем push в фазу 4.
- Ограниченный доступ к фоновым процессам — не критично для MVP.
- Фоновые процессы ограничены, зато есть квоты браузеров на хранилище (IndexedDB на iOS — evictable storage); риск смягчаем синком в облако.

### Нейтральные
- Хостинг статический — любой CDN.
