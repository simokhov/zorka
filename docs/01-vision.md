# Vision и требования

## 1. Видение

**«Зорька» — карманный помощник рыболова.** Приложение фиксирует каждую поимку вместе с её контекстом (место, погода, снасть), накапливает личную статистику и помогает отвечать на главный вопрос рыболова: *«где, когда и на что клевало?»*

Название отсылает к утренней заре — времени лучшего клёва.

## 2. Целевая аудитория

- **Этап 1 (MVP):** автор и друзья, закрытый доступ по приглашениям. Цель — обкатать функциональность на реальных выездах.
- **Этап 2:** публичный продукт с открытой регистрацией. Архитектура MVP должна выдержать этот переход без переписывания.

Первоначальная аудитория — русскоязычные рыболовы-любители, ловящие с берега и лодки на пресноводных и морских водоёмах.

## 3. Ценности продукта

1. **Не мешает рыбачить.** Запись поимки — 15–30 секунд, одной рукой, на ходу, при ярком солнце.
2. **Работает без сети.** Ловля происходит там, где связь плохая. Запись локально — синхронизация потом.
3. **Контекст решает.** Каждая поимка автоматически обогащается погодой и координатами — это то, что превращает дневник в статистику.
4. **Фото — часть истории.** Не галерея, а улика: трофей привязан к записи.

## 4. Функциональные возможности (по доменам)

### 4.1 Учёт улова (MVP)
- Запись поимки: вид рыбы (из справочника), количество, вес, длина, снасть, наживка/приманка.
- Автоматические поля: дата/время, GPS-координаты, погода в момент поимки (тянет погодный сервис).
- Фото улова: 1–N снимков к записи.
- Редактирование и удаление записей, мягкое удаление (корзина).

### 4.2 Места ловли + карта (MVP)
- Сохранение любимых мест как именованных точек.
- Карта (Яндекс.Карты): точки поимок и сохранённые места, история по точке.
- Просмотр всех поимок в радиусе / на выбранном месте.

### 4.3 Погода и прогноз (MVP)
- Погода в момент поимки (автосбор: температура, давление, ветер, влажность).
- Текущая погода и прогноз для сохранённого места ловли на главной карте.
- Источник — OpenWeatherMap; ключи живут на бэкенде (Edge Function), не в клиенте.

### 4.4 Статистика и аналитика (MVP)
- Личная статистика: по видам, местам, периодам (месяц/сезон), снастям, приманкам.
- Трофеи: лучшие экземпляры по виду.
- Влияние погоды на клёв: агрегаты «улов по давлению/ветру/времени суток».

### 4.5 Дневник выездов (роадмап, после MVP)
- Текстовая запись о выезде: условия, впечатления, что сработало.
- Привязка выезда к месту и поимкам дня.

### 4.6 Будущее (роадмап)
- OAuth-провайдеры, публичная регистрация, инвайты.
- Прогноз клёва на основе накопленной статистики и погоды.
- Социальные функции: обмен местами/отчётами между друзьями.
- Push-уведомления (PWA) о благоприятном прогнозе.

## 5. Нефункциональные требования

| Категория | Требование |
|---|---|
| Платформа | PWA, mobile-first; установка на домашний экран; работа в мобильных браузерах |
| Оффлайн | Создание записей и просмотр кэшированных данных без сети; синхронизация при появлении связи (ADR-0004) |
| Производительность | Интерактивность < 2 с на среднем смартфоне; запись поимки без сети — мгновенно |
| Фото | Оригинал + сжатое превью; лимит хранения на пользователя (MVP: 2 ГБ) |
| Безопасность | Данные пользователя изолированы по `user_id` (RLS в Postgres); ключи внешних API — только на бэкенде |
| Приватность | Геоданные и фото — чувствительные данные; по умолчанию всё приватно; местоположение запрашивается только в момент записи |
| Языки интерфейса | Русский (MVP); архитектура — i18n-ready |
| Масштаб | Этап 1 — десятки пользователей; этап 2 — тысячи; не проектируем «впрок» выше этого |

## 6. Ограничения и допущения

- Виды рыбы — встроенный справочник, правим только мы (ADR-0009).
- Карты — только Яндекс.Карты (ADR-0005); абстрагируем слой карты, чтобы смена провайдера не переписала UI.
- Бэкенд — Supabase (ADR-0002): принимаем привязку к нему на этапе MVP, изолируем клиент от деталей через data-слой.
- Монетизация на MVP не проектируется.

## 7. Критерии успеха MVP

1. Автор и друзья активно используют приложение в течение сезона (≥ 70% выездов фиксируются).
2. Запись поимки в оффлайне не теряется ни в одном воспроизводимом сценарии.
3. Статистика отвечает на вопросы «на что лучше клевало в этом месте в мае» без ручных подсчётов.
4. Переход к публичной регистрации требует только конфигурации, не миграций архитектуры.
