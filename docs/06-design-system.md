# Дизайн-система

Визуальное направление «Зорьки»: спокойная природная палитра, светлый серо-голубой фон, белые карточки с мягкими радиусами, тонкие границы и очень мягкие тени. Обоснование выбора — [ADR-0010](adr/0010-visual-direction.md). Макеты экранов — [design/zorka-ui.html](../design/zorka-ui.html).

Документ описывает токены и компоненты, обязательные для реализации (фаза 1 каркаса, [роадмап](04-roadmap.md)). Значения токенов сняты инструментально с утверждённого макета (квантование изображения + кластеризация по HSV) и переносятся в код без изменений.

## 1. Принципы

1. **Фото — главный визуальный герой.** Интерфейс не конкурирует с фотографией улова: приглушённые поверхности, тонкие линии, отсутствие ярких заливок на больших площадях.
2. **Читаемость на ярком солнце.** Светлый фон и тёмный петроль текста дают высокий контраст; насыщенность цвета отдана только смыслу, не декору.
3. **Тил = действие.** Акцентный тил применяется к основному действию экрана (одна кнопка-акцент на экран) и к активному элементу навигации. Остальные элементы нейтральны.
4. **Цвет — это состояние, а не украшение.** Амбер означает оффлайн/ожидание/трофей, зелёный — успешную синхронизацию, шалфей — карту, голубой тинт — иллюстрацию вида рыбы. Вне этих значений цвета не используются.
5. **Тонкая линия вместо тени.** Иерархия строится границей `1px` и фоном; тень — вспомогательный приём для всплывающих и залипающих элементов.
6. **Одна рука, один большой палец.** Основные действия — в нижней трети экрана, тап-таргет не меньше 44×44 px.

### 2.2 Правила использования

- **Порядок акцентов на экране:** одна primary-кнопка, один активный элемент навигации, дальше — нейтральные поверхности. Второе действие оформляется secondary/ghost.
- **Текст на цвете:** на `primary` и `primary-dark` — только `#FFFFFF`; на амберных подложках — `--color-amber-text` или `--color-ink`; на тинтах (blue, sage) и `--color-danger-bg` — `--color-ink` (на danger-диалогах — `--color-danger` для акцентных слов).
- **Амбер не используется для действий.** Это цвет состояния (нет сети, ожидание синхронизации, трофей), не цвет кнопки.
- **Зелёный не используется для кнопок.** Он сообщает результат, но не приглашает к действию.
- **Новые цвета не вводятся** без обновления этого документа и ADR: палитра закрыта, производные оттенки допускаются только как прозрачность (`rgba`) базового токена.

## 3. Типографика

**Гарнитура:** `Inter` (fallback — системный sans: `system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`). Шрифт подключается локально (self-host) — оффлайн-режим не должен зависеть от внешнего CDN.

| Токен | Размер / интерлиньяж | Насыщенность | Применение |
|---|---|---|---|
| `--font-display` | 28 px / 34 px | 500 | Заголовок экрана (Лента, Запись, Карта, Итоги) |
| `--font-h1` | 25 px / 32 px | 600 | Заголовок экрана входа |
| `--font-h2` | 19 px / 26 px | 600 | Заголовок шторки места, крупное значение (вес/длина, счётчик) |
| `--font-h3` | 15 px / 22 px | 600 | Название поимки в карточке, название вида в плитке |
| `--font-body` | 15 px / 22 px | 500 | Кнопки, значения погодной строки, названия полей |
| `--font-body-strong` | 17 px / 24 px | 600 | Акцентное значение (трофей, вес в степпере) |
| `--font-secondary` | 13 px / 18 px | 400 | Подзаголовок экрана, вторичные описания |
| `--font-meta` | 12 px / 16 px | 400 | Метаданные: дата, место, погода, координаты |
| `--font-label` | 11 px / 14 px, трекинг 0.06em, uppercase | 500 | Лейблы капсом: подписи полей, названия секций |
| `--font-tab` | 10 px / 12 px | 500 | Подписи нижнего таб-бара |

Правила: используются три начертания — 400 (обычный текст и метаданные), 500 (заголовки экранов, кнопки, лейблы) и 600 (акцентные значения, названия в карточках). Начертание 700 не используется. Цифры значений — табличные (`font-variant-numeric: tabular-nums`) в статистике и степперах.

## 4. Радиусы, отступы, границы

### 4.1 Радиусы

| Токен | Значение | Применение |
|---|---|---|
| `--radius-chip` | 999 px | Чипы-фильтры, пилюли, бейджи, аватары |
| `--radius-block` | 20 px | Крупные блоки: карточка трофея, шторка, баннер оффлайна, зона карты |
| `--radius-card` | 16 px | Карточки поимки, карточки статистики, поля ввода |
| `--radius-button` | 12 px | Кнопки, плитка вида рыбы, миниатюры фото |
| `--radius-sm` | 8 px | Мелкие элементы: иконка-контейнер, индикатор синхронизации |

### 4.2 Шкала отступов

Базовая сетка — 4 px.

| Токен | Значение | Типичное применение |
|---|---|---|
| `--space-1` | 4 px | Внутренние зазоры иконка↔текст |
| `--space-2` | 8 px | Зазор между чипами, строки внутри карточки |
| `--space-3` | 12 px | Внутренний паддинг карточки по горизонтали (компактный режим) |
| `--space-4` | 16 px | Паддинг карточки, боковые поля экрана |
| `--space-5` | 20 px | Паддинг крупных блоков |
| `--space-6` | 24 px | Между секциями экрана |
| `--space-8` | 32 px | Перед заголовком секции, отбивка групп |
| `--space-10` | 40 px | Верхний отступ заголовка экрана |

Боковое поле экрана — 16 px (`--space-4`). Нижний контент экрана дополняется отступом под таб-бар (высота таб-бара + `--space-4`), чтобы последняя карточка не уходила под панель.

### 4.3 Границы и тени

- Граница по умолчанию: `1px solid var(--color-border)` — у карточек, полей, чипов в активном состоянии.
- Толще 1 px границы не используются; разделение внутри карточки — граница или зазор, не «утолщение».
- Тень `--shadow-soft` — только у карточек на фоне `--color-bg`; карточка внутри карточки тени не имеет.
- Объёмных кнопок с жёсткой тенью (сдвиг 2–4 px вниз, насыщенный цвет) в системе нет — см. отвергнутую альтернативу в [ADR-0010](adr/0010-visual-direction.md).

## 5. Семантика цвета

| Смысл | Токены | Обязательное сопровождение |
|---|---|---|
| **Основное действие** | `--color-primary`, `--color-primary-dark` (pressed) | Существительное-глагол: «Сохранить поимку» |
| **Навигация (активный пункт)** | `--color-primary` + `--color-ink`, подпись `--font-tab` | Иконка активного пункта — залитая/акцентная, остальные — линейные `--color-ink-muted` |
| **Нет сети / оффлайн** | `--color-amber-bg`, `--color-amber-text`, `--color-amber-accent` | Текст «Нет сети» + пояснение, что запись сохранится локально |
| **Ожидание синхронизации (outbox)** | `--color-amber-accent`, `--color-amber-bg` | Иконка ожидания + счётчик записей в очереди |
| **Синхронизировано** | `--color-success` | Текст «✓ Синхронизировано»; без анимации-привлечения внимания |
| **Ошибка синхронизации** | `--color-amber-text` (текст), `--color-amber-bg` (подложка) | Прямая формулировка + действие «Повторить»; это исправимая ошибка — `--color-danger` не используется |
| **Необратимое действие** | `--color-danger` (кнопка-ссылка), `--color-danger-bg` (подложка диалога) | Слова «удалены навсегда» + диалог подтверждения с количеством записей и фото |
| **Трофей** | `--color-amber-bg` / `--color-amber-bg-alt`, `--color-amber-accent` | Подпись «Трофей» капсом `--font-label` |
| **Карта** | `--color-tint-sage` (подложка), маркеры — `--color-primary` | Точки поимок и места различаются формой/подписью, не цветом |
| **Вид рыбы (иллюстрация)** | `--color-tint-blue`, `--color-tint-blue-alt` | Плитка вида в форме записи и в статистике |

Красный/розовый для **исправимых** ошибок (синхронизация, валидация) не вводится: они подаются амбером с явным текстом. Отдельный `--color-danger` (приглушённый терракот `#B4543C`) введён решением от 2025-09-22 и применяется **только** к необратимым действиям — очистка корзины, удаление места с записями. Кричащий красный, заливки больших площадей и «злые» диалоги не используются: необратимость передаётся и цветом, и словами.

## 6. Компоненты

### 6.1 Кнопки

Общие параметры: высота 48 px (основная) / 40 px (компактная), паддинг по горизонтали `--space-5`, радиус `--radius-button`, шрифт `--font-body-strong`, иконка слева с зазором `--space-2`.

| Вариант | Фон | Текст | Граница | Применение |
|---|---|---|---|---|
| **Primary** | `--color-primary` (pressed `--color-primary-dark`) | `#FFFFFF` | нет | «Сохранить поимку», «Войти», «Записать поимку здесь» |
| **Secondary** | `--color-surface` | `--color-primary-deep-text` | `1px var(--color-border)` | Второе действие: «Добавить фото», «Выбрать на карте» |
| **Ghost** | прозрачный | `--color-primary-deep-text` | нет | Третичное действие: «Пропустить», «Отмена» |
| **Disabled** | `--disabled-bg` | `--disabled-text` | нет | Кнопка не активна (не заполнен обязательный вид рыбы) |

Правила: ширина primary-кнопки на мобильном — на всю ширину контейнера; состояние загрузки — тот же размер, текст заменяется индикатором, кнопка остаётся `disabled`; во время отправки формы повторный тап невозможен.

### 6.2 Чипы-фильтры

Пилюля `--radius-chip`, высота 32 px, паддинг 12 px по горизонтали, шрифт `--font-secondary`.

- **Неактивный:** фон `--color-surface`, текст `--color-ink-secondary`, граница `1px var(--color-border)`.
- **Активный:** фон `--color-primary`, текст `#FFFFFF`, границы нет.
- **Счётчик в чипе** (например, «Щука · 12») — `--font-meta`, в активном состоянии белый с прозрачностью 0.8.
- Ряд чипов прокручивается горизонтально, без переноса, с зазором `--space-2`; ряд не «прыгает» при выборе.

### 6.3 Карточка поимки

Структура (сверху вниз):

1. **Медиа-зона** — фото (превью, ADR-0007) или заглушка при отсутствии фото (см. §7.2). Радиус `--radius-card` сверху, соотношение сторон 4:3 для одиночного фото; при нескольких фото — горизонтальная прокрутка миниатюр `--radius-button`.
2. **Строка вида** — название вида `--font-h3` (`--color-ink`) + вес `--font-body-strong` справа.
3. **Метаданные** — `--font-meta`, `--color-ink-muted`: время поимки, место, снасть/приманка, погода. Разделитель — «·».
4. **Состояние** — бейдж синхронизации или бейдж «Трофей» (см. §6.11).

Оболочка: фон `--color-surface`, радиус `--radius-card`, паддинг `--space-4`, граница `1px var(--color-border)`, тень `--shadow-soft`. Карточки разделяются зазором `--space-3`, разделительных линий между карточками нет.

Вся карточка — одна тап-зона; отдельные действия (правка/удаление) живут внутри детального экрана.

### 6.4 Плитка вида рыбы

Элемент выбора вида в форме записи и в фильтрах: квадрат или прямоугольник 1:1, радиус `--radius-button`, фон — `--color-tint-blue` или `--color-tint-blue-alt` (чередование по позиции в сетке), внутри — линейная монохромная иконка вида (`--color-ink`) и подпись `--font-secondary` (`--color-ink`).

- Иконка берётся по коду `species.icon` ([справочник видов](05-species-catalog.md)); неизвестный код → дефолтная иконка `fish`.
- Выбранная плитка: граница 2 px `--color-primary` и фон `--color-surface`; вариант с заливкой `--color-primary` не используется — тинт остаётся фоном иллюстрации, чтобы сетка не становилась цветным пятном.
- Сетка — 3 колонки с зазором `--space-2`.
- Поиск по справочнику — поле ввода с плавающим лейблом (§6.9) над сеткой; при пустом результате — плитки не показываются, выводится текст `--font-secondary` `--color-ink-muted` «Вид не найден» и подсказка про пополнение справочника.

### 6.5 Степпер веса / длины

Компонент числового ввода с шагом, основной способ ввода веса и длины одной рукой.

- Компоновка: слева — кнопка «−», по центру — значение и единица, справа — кнопка «+». Кнопки 44×44 px, радиус `--radius-sm`, фон `--color-surface-alt`, иконка `--color-ink`.
- Значение — `--font-h3` `--color-ink`, цифры табличные; единица измерения — `--font-meta` `--color-ink-muted` («г» / «мм»).
- Долгое нажатие — ускоренное изменение шага; шаг: 50 г для веса, 10 мм для длины.
- Значение редактируется и тапом по числу (открывается числовая клавиатура) — степпер не единственный путь ввода.
- Пустое значение показывается как «—» (`--color-ink-muted`); поля необязательны, пустое значение не блокирует сохранение.
- Ошибка диапазона — текст `--font-secondary` под степпером цветом `--color-amber-text`; ввод при этом не сбрасывается.

### 6.6 Баннер оффлайна

Полоса во всю ширину над контентом (под заголовком экрана), фон `--color-amber-bg`, радиус `--radius-card`, паддинг `--space-3` `--space-4`, иконка сети `--color-amber-accent`, текст «Нет сети» — `--font-body-strong` `--color-amber-text`.

Вторая строка — пояснение `--font-meta` `--color-ink-secondary`: «Запись сохранится на устройстве и отправится при появлении связи». Баннер не перекрывает контент и не блокирует действия; форма записи поимки в оффлайне работает полностью (ADR-0004).

### 6.7 Карточка трофея

Отдельная карточка в статистике и в детальном экране вида: подложка `--color-amber-bg` (вариант — `--color-amber-bg-alt`), радиус `--radius-block`, паддинг `--space-5`.

- Слева — фото или плитка вида; справа — подпись «ТРОФЕЙ» `--font-label` `--color-amber-text`, вес `--font-h2` `--color-ink`, ниже — дата и место `--font-meta` `--color-ink-muted`.
- Иконка трофея — линейная, `--color-amber-accent`.
- В ленте трофейная поимка дополнительно получает бейдж «Трофей» (§6.11), но основная карточка остаётся белой: амбер — маркер, не фон ленты.

### 6.8 Погодная строка

Компактная строка метаданных: линейная иконка погоды + температура `--font-body-strong` `--color-ink` + ветер/давление `--font-meta` `--color-ink-muted`, разделитель «·». Фон — `--color-surface-alt`, радиус `--radius-chip`, паддинг `--space-1` `--space-3`.

Состояния: **есть данные** — как выше; **данных нет** — текст «Погода не записана» `--color-ink-muted` без иконки (см. §7.3); **загружается** — скелетон-плашка того же размера на `--color-surface-alt`.

### 6.9 Поля ввода с плавающим лейблом

- Контейнер: фон `--color-surface`, граница `1px var(--color-border)`, радиус `--radius-card`, высота 56 px, паддинг `--space-4`.
- **Пустое поле** — лейбл внутри контейнера: `--font-body` `--color-ink-muted`.
- **В фокусе или заполнено** — лейбл поднимается вверх, уменьшается до `--font-label`, окрашивается в `--color-primary-deep-text`; значение — `--font-body` `--color-ink`.
- **Фокус** — граница `1px var(--color-primary)` + `--focus-ring`; тень поля не используется.
- **Ошибка** — граница `1px var(--color-amber-accent)`, текст ошибки `--font-secondary` `--color-amber-text` под полем.
- **Disabled** — фон `--color-surface-alt`, лейбл и значение `--color-ink-muted`.
- Многострочная заметка — тот же контейнер, высота по контенту, начинается от 96 px.

### 6.10 Таб-бар

Нижняя навигация из четырёх пунктов: **Лента / Запись / Карта / Итоги**.

- Контейнер: фон `--color-surface`, верхняя граница `1px var(--color-border)`, тень `--shadow-sticky`, высота 56 px + safe-area (`env(safe-area-inset-bottom)`), паддинг `--space-2` `--space-4`.
- Пункт: иконка 24 px + подпись `--font-tab`; тап-таргет не меньше 44×44 px.
- **Неактивный пункт:** иконка и подпись `--color-ink-muted`, иконка линейная.
- **Активный пункт:** иконка и подпись `--color-primary`, иконка залитая/акцентная; подписи меняют начертание на 500.
- **Пункт «Запись»** — центральный, оформляется как акцентная кнопка-круг 56 px в `--color-primary` с иконкой `#FFFFFF`, выступающая на `--space-2` над линией таб-бара: это главный сценарий продукта.
- Бейдж непрочитанного/ожидающего (число записей в outbox) — точка 8 px `--color-amber-accent` в правом верхнем углу иконки, с числом — только если записей больше одной.

### 6.11 Состояния синхронизации

Один компонент — компактный бейдж внутри карточки поимки (иконка `--radius-sm` + текст `--font-meta`). Состояния соответствуют модели outbox (ADR-0004, [модель данных](03-data-model.md)):

| Состояние | Визуал | Текст |
|---|---|---|
| `pending` — в очереди outbox | фон `--color-amber-bg`, иконка `--color-amber-accent` | «Ждёт отправки» |
| `syncing` — идёт досылка | фон `--color-surface-alt`, иконка `--color-ink-muted` с индикатором | «Отправляем…» |
| `synced` (`synced: ok`) | без подложки, иконка и текст `--color-success` | «✓ Синхронизировано» |
| `error` — сервер отклонил, повтор | фон `--color-amber-bg`, текст `--color-amber-text` | «Не отправлено · Повторить» (`--color-primary-deep-text`, тап-зона 44 px) |

Правила: состояния `pending`/`error` не скрываются из ленты и не «висят» модальным окном; счётчик очереди доступен в шапке ленты и в таб-баре; переход `pending → synced` не сопровождается анимацией, привлекающей внимание (запись не должна «прыгать» в списке). Детальные правила оффлайна — [ADR-0004](adr/0004-partial-offline.md).

## 7. Правила поведения интерфейса

### 7.1 Оффлайн и синхронизация

1. **Запись поимки не блокируется отсутствием сети.** Форма доступна всегда; при оффлайне над заголовком показывается баннер (§6.6), а после сохранения карточка появляется в ленте с бейджем «Ждёт отправки» — визуально это обычная карточка, не «серая» и не уменьшенная.
2. **Состояние видно в трёх местах:** баннер оффлайна (факт отсутствия сети), бейдж на карточке (судьба конкретной записи), счётчик в таб-баре (объём очереди).
3. **Нет модальных окон про сеть.** Предупреждение об оффлайне никогда не перекрывает форму и не требует подтверждения.
4. **Ошибка синхронизации подаётся амбером**, не красным: текст «Не отправлено», действие «Повторить», данные записи не теряются.
5. **Успех не празднуется.** «✓ Синхронизировано» — тихий бейдж `--color-success`; никаких тостов-поздравлений поверх контента.
6. **Фото в очереди** показываются локальным blob-превью; после подтверждения сервера — превью по signed URL (ADR-0007). Визуально подмена не сопровождается индикатором: пользователь видит одно и то же фото.
7. **Редактирование доступно только синхронизированным записям** (ADR-0004). Пока запись в очереди, кнопка «Редактировать» в детальном экране находится в состоянии disabled (`--color-surface-alt`, `--color-ink-faint`), под ней — сноска «Станет доступно после синхронизации записи» `--font-meta`.

### 7.2 Запись без фото

- Карточка сохраняет полноценную структуру: **медиа-зона не исчезает**, вместо фото — заглушка с фоном `--color-tint-blue`/`--color-tint-blue-alt` и линейной иконкой вида рыбы `--color-ink` (та же плитка вида, что в §6.4), без текста «нет фото».
- Высота заглушки — меньше фотографии (соотношение 16:9 вместо 4:3), чтобы записи без фото не занимали столько же места в ленте.
- В детальном экране на месте медиа-зоны — блок «Добавить фото»: пунктирная граница `1px var(--color-border)`, иконка камеры `--color-ink-muted`, текст `--font-secondary`.
- Отсутствие фото не влияет на статистику и не помечается как неполнота записи.

### 7.3 Отсутствие погоды

- Погодная строка показывает «Погода не записана» (`--color-ink-muted`), без иконки, без амбер-предупреждения: пустая погода — не ошибка пользователя.
- Если снимок погоды будет дозаполнен при первой синхронизации (ADR-0006), строка обновляется на месте, без перезагрузки экрана и без бейджа «обновлено».
- В статистике поимки с пустой погодой не учитываются в агрегатах «погода vs клёв», но остаются во всех остальных; в интерфейсе агрегата выводится сноска «N поимок без данных о погоде» `--font-meta` `--color-ink-muted`.
- Сбой погодного провайдера не меняет внешний вид формы записи — сохранение поимки не зависит от погоды.

### 7.4 Общие ограничения

- Скелетоны загрузки — плашки `--color-surface-alt` с радиусом целевого элемента; спиннер на весь экран не используется.
- Пустое состояние списка: линейная иконка `--color-ink-muted`, заголовок `--font-h3`, одна строка пояснения `--font-secondary` и одно действие (primary или secondary).
- Иконки — только тонкие линейные, толщина штриха 1.5 px, размеры 16/20/24 px, цвет наследуется (`currentColor`) от текста.
- Анимации — только функциональные (появление шторки, смена состояния элемента), длительность 150–200 мс; декоративных «пружин» и подсветок нет.

### 7.5 Мягкое удаление и корзина

- **Удаление — это «В корзину», не «Удалить навсегда».** Действие в детальном экране — text-btn `--color-ink-muted` в нижней группе кнопок, не primary и не на видном месте: случайное касание не должно удалять запись. Запись получает `deleted_at` ([03-data-model.md](03-data-model.md)), исчезает из ленты и статистики, фото сохраняются до истечения срока.
- **Корзина хранит записи 30 дней.** Подзаголовок экрана сообщает срок; каждая карточка показывает, когда запись удалена («удалено вчера», «удалено 3 дня назад»), — счётчик срока виден без дополнительных действий.
- **Восстановление — primary-пилюля «Восстановить» на карточке**, без перехода в детальный экран. Восстановленная запись возвращается в ленту и статистику по своей дате поимки, бейдж синхронизации не показывается: восстановление — серверная операция, недоступная оффлайн.
- **Очистка корзины — необратимое действие.** Выполняется кнопкой-ссылкой «Очистить корзину» цветом `--color-danger` с сноской «Записи и фото будут удалены навсегда»; подтверждение — отдельным диалогом (подложка `--color-danger-bg`) с перечислением количества записей и фото. Цветом передаётся необратимость, но не «крик»: заливок и яркого красного нет (решение от 2025-09-22, §5).
- **Записи в корзине и в очереди отправки не редактируются** (ADR-0004): их детальный экран показывает только просмотр.

## 10. Открытые вопросы

1. **Название приложения — решено.** Продукт называется «Зорька»; «Дневник рыбака» — подзаголовок экрана входа (решение заказчика от 2025-09-22). На экране входа заголовок «Зорька», под ним «Дневник рыбака: места, уловы и наблюдения».
2. **Цвет ошибки — решено.** Введён `--color-danger` `#B4543C` (+ `--color-danger-bg` `#F8E9E4`) — приглушённый терракот в тон палитры, **только** для необратимых действий (решение заказчика от 2025-09-22). Исправимые ошибки (синхронизация, валидация) остаются амбером (§5).
3. **Тёмная тема.** Не рассматривалась; при ночной ловле тёмный режим может быть востребован. Требует отдельного набора токенов (фон, поверхности, тинты) — отдельное решение.
4. **Шрифт.** Inter — допущение; план фазы 1 (этап 2) фиксирует self-host woff2 с усечённым набором глифов (латиница + кириллица) и `font-display: swap` — [07-phase1-plan.md](07-phase1-plan.md).
5. **Стилевой слой реализации — решено.** CSS Modules (решение от 2025-09-22, зафиксировано в [ADR-0003](adr/0003-frontend-stack.md)): токены уже CSS-переменные, стили макетов переносятся напрямую.
6. **Иллюстрации видов рыбы.** Сейчас — линейные иконки по коду `species.icon`; рисованные иллюстрации на голубом тинте улучшили бы ленту, но требуют отдельного набора ассетов для 51 вида.
7. **Размер таб-бара и safe-area** на устройствах с «домашней полосой» — проверить на реальных устройствах; включено в этап 5 [плана фазы 1](07-phase1-plan.md).
8. **Число пунктов навигации.** В макете четыре пункта (Лента / Запись / Карта / Итоги); при появлении дневника выездов (фаза 4) потребуется решение — пятый пункт, раздел внутри «Итогов» или «Ещё».

## 11. Перенос в код

Токены переносятся без переименований и без «подгонки» значений — HEX из §2.1 попадают в CSS-переменные (`:root`) один в один; компоненты используют только токены, литеральные HEX в коде компонентов запрещены. Исключение — прозрачные производные (§2.3), которые выражаются через базовый токен.

Структура слоя стилей (по слоям [02-architecture.md](02-architecture.md)):

```
src/styles/tokens.css      — переменные §2–§4
src/styles/base.css        — reset, типографика, фон приложения
src/ui/                    — переиспользуемые компоненты §6
src/features/*/            — экраны доменов (catches, map, places, weather, stats, auth)
```

Контроль: визуальная проверка компонентов на реальном устройстве при ярком освещении — часть приёмки фазы 1; отклонение от токенов фиксируется в этом документе, а не в коде.
